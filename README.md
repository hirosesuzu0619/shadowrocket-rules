# shadowrocket-rules

存放个人使用的 Shadowrocket 模块与规则。仓库是公开的，因此这里不包含订阅链接、节点信息等任何私密内容。

## 文件说明

`modules/personal.module` 是个人最高优先级规则层，也就是设备上本地加载的「个人」模块。
它只包含 `[Rule]` 段，声明哪些域名走代理、直连或屏蔽，规则里引用的策略组名（`US`、`TW`、`SG`、`JP`）由 Shadowrocket 在运行时按名字解析。
因为是本地模块，任何远程模块的自动更新都不会覆盖它，请在模块列表里把它排在其他模块之上，让它的规则先被命中。

`modules/region-groups.module.example` 是地区策略组的模板，只在你想用模块而非图形界面管理策略组时才需要，用法见下。

## 策略组

规则里引用的组名需要存在同名策略组才会生效。目前四个地区分组是在 Shadowrocket 图形界面里建立的：`US`、`TW`、`SG`、`JP`。
在界面里建组的好处是订阅按 App 内已有的条目被引用，链接不会出现在任何文件里——新建策略组时打开「订阅」开关并勾选订阅，下方会列出全部节点，再用正则筛选出目标地区。

四个地区的筛选正则如下，重装或换设备时照抄即可：

```
US: (?i)(美国|美國|洛杉矶|洛杉磯|圣何塞|聖何塞|西雅图|西雅圖|硅谷|凤凰城|鳳凰城|达拉斯|達拉斯|纽约|紐約|波特兰|波特蘭|拉斯维加斯|拉斯維加斯|United States|\bUSA?\b|🇺🇸)
TW: (?i)(台湾|台灣|臺灣|台北|臺北|新北|彰化|高雄|新竹|Taiwan|\bTW\b|🇹🇼)
SG: (?i)(新加坡|狮城|獅城|星加坡|Singapore|\bSG\b|🇸🇬)
JP: (?i)(日本|东京|東京|大阪|名古屋|埼玉|川日|沪日|滬日|Japan|\bJP\b|🇯🇵)
```

筛选依据是节点名称，所以正则里同时写了简体、繁体和英文；`US`、`TW` 这类两字母缩写加了 `\b` 单词边界，避免把 `AUS` 之类的名字误判进来。节点命名风格因机场而异，建好后看一眼实际匹配到的节点，按需补关键字。

### 手动还是自动测速

组内只有一个节点时用手动即可，自动测速在唯一候选之间做不出选择，只会多出周期性探测流量。
当某个地区攒到多个节点时，把该组改成自动测速（`url-test`）才有价值：它按延迟择优，并在节点失效时自动切换。

### 用模块管理策略组

如果更想把策略组也纳入版本管理，把 `modules/region-groups.module.example` 复制成 `modules/region-groups.local.module`，填入订阅链接后放到本地 HTTP 服务上加载。`.gitignore` 已忽略 `*.local.module`，不会误提交。
启用前务必删除 App 里手工建立的同名分组：同一个组名在配置和模块中各出现一次会产生冲突，表现为改了模块不生效，或分组列表出现重复项。
另外订阅链接等同于凭据，一旦提交进 git 就会留在历史里，公开仓库的历史任何人可读，那时唯一可靠的处理是找机场重置链接。

## 规则怎么写

格式是 `类型,值,策略`。精确匹配用 `DOMAIN`，后缀匹配用 `DOMAIN-SUFFIX`，关键字匹配用 `DOMAIN-KEYWORD`；策略可以填 `US`、`TW`、`SG`、`JP` 这类策略组名，也可以填 `DIRECT` 直连或 `REJECT` 屏蔽。
当前规则把 Siri 与 Apple 隐私中继相关的域名统一指向 `US`。其中 `DOMAIN-KEYWORD,siri,US` 是关键字匹配，凡域名含 siri 都会命中，范围比其他几条宽，若出现误伤可改成更精确的写法。
