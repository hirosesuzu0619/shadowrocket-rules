# shadowrocket-rules

存放个人使用的 Shadowrocket 模块与规则。仓库是公开的，因此这里不包含订阅链接、节点信息等任何私密内容。

## 文件说明

`modules/personal.module` 是个人最高优先级规则层，也就是设备上本地加载的「个人」模块。
它只包含 `[Rule]` 段，声明哪些域名走代理、直连或屏蔽，规则里引用的策略组名（`US`、`TW`）由 Shadowrocket 在运行时按名字解析。
因为是本地模块，任何远程模块的自动更新都不会覆盖它，请在模块列表里把它排在其他模块之上，让它的规则先被命中。

`modules/region-groups.module.example` 是地区策略组的模板，只在你确实想用模块形式定义策略组时才需要，用法见下。

## 策略组怎么建

规则里的 `US` 和 `TW` 需要存在同名策略组才会生效。推荐直接在 Shadowrocket 图形界面里建，这样订阅是按 App 内已有的条目被引用的，链接不会出现在任何文件里：

在「配置」中新建策略组，类型选 `url-test`（自动测速择优），名称填 `US`，打开「订阅」开关并勾选你的订阅，下方就会列出该订阅的全部节点，再在正则筛选框里填入下面的表达式。`TW` 组同理。

美国：

```
(?i)(美国|美國|洛杉矶|洛杉磯|圣何塞|聖何塞|西雅图|西雅圖|硅谷|凤凰城|鳳凰城|达拉斯|達拉斯|纽约|紐約|波特兰|波特蘭|拉斯维加斯|拉斯維加斯|United States|\bUSA?\b|🇺🇸)
```

台湾：

```
(?i)(台湾|台灣|臺灣|台北|臺北|新北|彰化|高雄|新竹|Taiwan|\bTW\b|🇹🇼)
```

筛选依据是节点名称，所以正则里同时写了简体、繁体和英文；`US`、`TW` 这类两字母缩写加了 `\b` 单词边界，避免把 `AUS` 之类的名字误判进来。节点名称的命名风格因机场而异，建好之后在组里看一眼实际匹配到的节点，按需要补关键字。

如果你更想用模块而不是图形界面来管理策略组，把 `modules/region-groups.module.example` 复制成 `modules/region-groups.local.module`，填入订阅链接后放到本地 HTTP 服务上加载。`.gitignore` 已经忽略了 `*.local.module`，不会误提交。订阅链接本身等同于凭据，一旦提交进 git 就会留在历史里，那时唯一可靠的处理是找机场重置链接。

## 规则怎么写

格式是 `类型,值,策略`。精确匹配用 `DOMAIN`，后缀匹配用 `DOMAIN-SUFFIX`，关键字匹配用 `DOMAIN-KEYWORD`；策略可以填 `US`、`TW` 这类策略组名，也可以填 `DIRECT` 直连或 `REJECT` 屏蔽。
当前规则把 Siri 与 Apple 隐私中继相关的域名统一指向 `US`。其中 `DOMAIN-KEYWORD,siri,US` 是关键字匹配，凡域名含 siri 都会命中，范围比其他几条宽，若出现误伤可改成更精确的写法。
